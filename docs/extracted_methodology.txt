V. PROPOSED METHODOLOGY
The proposed framework examines whether query-adaptive fusion of colour and texture information can improve content-based image retrieval compared with conventional fixed-weight fusion. The complete pipeline includes dataset preparation, colour and texture feature extraction, gallery-based normalization, baseline retrieval, adaptive weight prediction using a Multi-Layer Perceptron (MLP), distance-based ranking, and quantitative evaluation.
A. Dataset Preparation
All experiments are conducted using the Corel-1K dataset, containing 1,000 images distributed equally across 10 semantic categories. Each category contains 100 images. A fixed random seed of 42 is used to maintain a reproducible query-gallery partition. For every category, 10 images are selected as queries and the remaining 90 images form the gallery, resulting in 100 query images and 900 gallery images. The final 100 query images are completely isolated from M5 training and validation. They are not used for training, validation, hyperparameter selection, or early stopping and are used only for final evaluation.
B. HSV Colour Feature Extraction
Colour information is represented in the HSV colour space. The Hue, Saturation, and Value channels are processed independently. For each channel, three statistical descriptors are calculated: mean, standard deviation, and skewness. The resulting colour vector is defined as:
C = [μH, σH, sH, μS, σS, sS, μV, σV, sV]
where μ, σ, and s denote the mean, standard deviation, and skewness, respectively. This procedure produces a 9-dimensional colour representation for every image.
C. GLCM Texture Feature Extraction
Texture information is extracted independently using the Gray-Level Co-occurrence Matrix (GLCM). Each image is converted to grayscale, and co-occurrence information is calculated using a pixel distance of one at four orientations: 0°, 45°, 90°, and 135°. Four properties—contrast, correlation, energy, and homogeneity—are calculated for each orientation and then averaged. The resulting texture vector is:
T = [Contrast, Correlation, Energy, Homogeneity]
Thus, each image is represented by four texture features. Combining the colour and texture descriptors gives an initial 13-dimensional representation.
D. Gallery-Based Feature Normalization
The extracted colour and texture descriptors have different numerical ranges. To make their contributions comparable, Min-Max normalization is applied separately to both feature groups. For each feature, the minimum and maximum values are calculated using only the 900 gallery images. The normalized value is obtained as:
x̂ = (x − xmin) / (xmax − xmin)
where xmin and xmax are the corresponding minimum and maximum values calculated from the gallery. The same fitted parameters are then applied to both gallery and query features. This prevents information from the final query set from affecting the normalization stage.
E. Baseline Retrieval Models
Four baseline configurations are used to establish a controlled comparison with the proposed adaptive model.
M1 — Colour Only: M1 uses the normalized HSV colour representation. The colour distance between a query q and gallery image x is calculated using Euclidean distance:
DC(q,x) = ||Cq − Cx||₂
M2 — Texture Only: M2 uses only the normalized GLCM texture representation:
DT(q,x) = ||Tq − Tx||₂
M3 — Equal Fusion: M3 combines the normalized colour and texture representations using fixed coefficients wC = 0.5 and wT = 0.5. Its Euclidean distance is:
DM3(q,x) = √(0.25 DC²(q,x) + 0.25 DT²(q,x))
M4 — Fixed Fusion: M4 applies a colour-dominant fixed configuration with wC = 0.7 and wT = 0.3. The corresponding distance is:
DM4(q,x) = √(0.49 DC²(q,x) + 0.09 DT²(q,x))
The M4 weights are fixed before evaluation and are not optimized using the final query set.
F. Proposed Query-Adaptive Fusion Model (M5)
M5 replaces the fixed fusion coefficients used by M3 and M4 with query-specific weights generated by a lightweight MLP. For each query, the nine normalized colour features and four normalized texture features are concatenated to form a 13-dimensional input vector:
Xq = [Cq, Tq] ∈ R¹³
The MLP follows a 13–16–8–2 architecture with LeakyReLU activation functions with a negative slope of 0.1. The two output values are converted into colour and texture weights using Softmax:
[wC(q), wT(q)] = Softmax(zq)
This constrains both weights to be non-negative and ensures that wC(q) + wT(q) = 1. Consequently, the relative contribution of colour and texture can change from one query to another.
G. Adaptive Distance Calculation
For each query-gallery pair, ordinary Euclidean distances are first calculated independently in the normalized colour and texture spaces. The query-specific M5 weights are then applied to obtain the adaptive distance:
DM5(q,x) = √(wC(q) DC²(q,x) + wT(q) DT²(q,x))
Gallery images are ranked in ascending order of DM5, where a smaller distance indicates greater visual similarity.
H. M5 Training Procedure
M5 is trained only on the 900-image gallery. The gallery is divided into an internal training set of 700 images and a validation set of 200 images, corresponding to 70 and 20 images per category, respectively. Training is formulated as metric learning using triplets (q, p, n), where q is an anchor, p belongs to the same category, and n belongs to a different category. The triplet objective is:
L = max(0, DM5²(q,p) − DM5²(q,n) + m)
where the margin m is fixed at 0.15. The model is optimized using Adam with a learning rate of 0.001 and a batch size of 64. Early stopping is based on the internal validation loss, and the best-performing checkpoint is retained. The isolated 100-query set is never used during this learning procedure.
I. Retrieval and Evaluation
After training, M5 predicts query-specific weights for each of the 100 isolated queries. Every query is compared with all 900 gallery images using the corresponding retrieval distance. The top 10 ranked results are used to calculate Precision@10, Recall@10, and F1-score@10. Recall@10 uses the 90 relevant gallery images associated with each query. Mean Average Precision (mAP) is calculated over the complete gallery, and average retrieval time per query is recorded to assess computational cost. M5 is evaluated using exactly the same isolated query set and gallery used for comparison with M1–M4.
